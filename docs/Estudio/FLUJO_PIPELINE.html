1

Datos llegan a S3 (bucket raw)

El archivo events.jsonl (~166 MB, 1 M+ eventos de comportamiento de usuarios) se sube al bucket con prefijo year=2024/month=03/day=15/. Cada línea es un evento: page view, click, scroll, purchase.

S3 · shopstream-raw-data-… Partición hive-style 1 M+ eventos
2

Lambda convierte JSON → Parquet

El evento s3:ObjectCreated:* activa automáticamente la función Lambda. Convierte el archivo JSON a Parquet con compresión Snappy y lo escribe en el bucket processed. El trigger :* captura también uploads multiparte (archivos >8 MB).

Lambda · shopstream-raw-to-parquet Parquet + Snappy S3 processed
3

EMR calcula 6 métricas con PySpark

Un cluster EMR (1 master + 2 workers) lee los Parquet y genera 6 DataFrames de análisis: tiempo por página, sesiones por dispositivo+país, top páginas, comparativas de bounce rate, patrones temporales y anomalías con z-score.

EMR 6.15.0 · PySpark 6 métricas Z-score + IQR anomalías → S3 processed/aggregated/
4

Glue Catalog indexa los archivos

AWS Glue Crawler descubre los archivos Parquet en S3 y registra 7 tablas en el catálogo shopstream_glue_db. A partir de aquí cualquier servicio AWS puede consultar los datos con SQL sin moverlos.

Glue Catalog · shopstream_glue_db 7 tablas registradas
5

Glue ETL carga el Data Warehouse

El Glue Job Visual ETL lee del catálogo, aplica un nodo de Data Quality con 5 reglas (completeness, rango de valores), hace ApplyMapping para renombrar columnas y escribe vía JDBC en PostgreSQL. Se ejecuta diario a las 2 AM UTC mediante un Glue Workflow.

Glue Visual ETL Data Quality · 5 reglas 3 tablas de hecho cargadas Cron: 0 2 * * ?
6

Data Warehouse en PostgreSQL (RDS)

Base de datos shopstream en RDS PostgreSQL dentro de VPC. Esquema estrella: 3 dimensiones (users, products, dates) y 6 tablas de hecho con los resultados del análisis. Aquí viven los 20 top pages, 362 anomalías y los resúmenes de sesión.

RDS PostgreSQL · shopstream.* 3 dim + 6 fact 20 / 24 / 362 filas
7

API REST expone los datos al mundo

Flask con 3 endpoints desplegada en Lambda vía Zappa + API Gateway. Conecta directamente a RDS con psycopg2. 13 tests unitarios, CI/CD con GitHub Actions (flake8 + pytest en cada push). Responde en JSON listo para consumir.

Flask · Lambda · Zappa 3 endpoints activos 13 tests · CI/CD GitHub Actions
