5Preguntas frecuentes del profe (y cómo responder)

¿Por qué usaron Lambda para la ingesta y no Glue directamente?
Lambda es el mecanismo de trigger nativo de S3. Reacciona en tiempo real a cada archivo subido (event-driven), mientras Glue está pensado para jobs batch programados. La Lambda valida, cuarentena y registra métricas — es el "portero" del pipeline. Glue entra después, cuando los datos ya fueron catalogados.
¿Por qué s3:ObjectCreated:* y no s3:ObjectCreated:Put?
Porque boto3 usa multipart upload automáticamente para archivos mayores a 8 MB. En ese caso S3 emite el evento CompleteMultipartUpload, no Put. Si usáramos solo Put, los eventos.jsonl de 166 MB nunca dispararían la Lambda. El wildcard ObjectCreated:* captura ambos.
¿Qué hace el nodo Data Quality en Glue Studio?
Valida que los registros que van a RDS cumplan reglas mínimas: que page_url y date no sean nulos, que avg_time_seconds sea no negativo, que total_views sea no negativo y que bounce_rate esté entre 0 y 100. Los registros que no pasan se desvían a una salida separada, no contaminan el datawarehouse.
¿Qué significa el trigger condicional en Glue?
El workflow tiene dos jobs: primero el ETL (S3 a RDS). El trigger condicional solo activa la segunda etapa (carga final y crawl) si el ETL terminó con estado SUCCEEDED. Si falla, en lugar de correr la segunda etapa, el SNS envía un email de alerta. Así evitamos cargar datos incompletos al datawarehouse.
¿Cómo detectan las anomalías?
Usamos dos métodos estadísticos combinados. Z-score: calculamos media y desviación estándar del tiempo total de sesión; si |z| > 3 es anómalo. IQR: calculamos Q1 y Q3; si el valor cae fuera de [Q1 - 1.5·IQR, Q3 + 1.5·IQR] es outlier. Una sesión se marca anómala si dispara cualquiera de los dos criterios.
¿Por qué Zappa para la API y no un API Gateway manual?
Zappa automatiza todo el empaquetado de Flask a Lambda y la creación del API Gateway. En AWS Academy no podemos crear roles IAM nuevos; Zappa acepta role_name: LabRole en su configuración. Una sola línea (zappa deploy production) despliega todo.
¿Por qué star schema en el datawarehouse?
El star schema separa las dimensiones (páginas, dispositivos, productos — datos que cambian poco) de los hechos (métricas calculadas por día — datos que crecen constantemente). Esto optimiza las consultas analíticas de la API, que siempre filtran por fecha y agregan por dimensión.
¿Cuántos tests tienen y qué cubren?
17 tests del generador (conteos, tipos, distribuciones, integridad referencial), 19 del validador (campos requeridos por tipo, rangos, timestamps, enums), 4 del handler Lambda con moto (mock de S3 y CloudWatch), 13 de la API Flask (mock de BD, validación de parámetros, respuestas). Total: más de 53 tests en verde.
